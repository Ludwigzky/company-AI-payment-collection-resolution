# 企业回款方案生成演示

输入欠款金额、约定付款到期日和项目问题，生成维修整改、商务催收、法务路径与条件性投诉建议。业务优先级按用户确认的频率排列：设备销售、安装或维保，其次为一般企业应收账款，再次为工程结算。

## 本地启动

需要 Node.js 20 或更新版本，无需安装第三方依赖。在本目录执行：

```powershell
npm run dev
```

打开终端打印的本机地址，默认是 `http://127.0.0.1:4173/`。默认端口被占用时会向后尝试端口。服务仅监听本机，关闭终端中的服务后即停止。

## 演示功能

- 三类虚构示例，可直接修改金额、到期日、问题及补充条件。
- 按维修、验收、资金、开票及争议情况组合行动步骤、负责人、材料和推进条件。
- 根据付款节点区分未到期、今日到期和逾期；金额及日期都有输入校验。
- 核查合同争议约定后分流诉讼或仲裁，不直接将“有欠款”认定为具备起诉条件。
- 中小企业款项投诉同时核查主体、事项及已有受理情况；纯企业经营货款不直接套用消费投诉。
- 展示证据清单、待补充问题、事实记录和业务沟通函草稿。
- 支持文本方案下载、草稿复制，以及通过浏览器打印或保存 PDF。
- 法律与渠道页提供官方全文或办事入口、条号定位、资料核查日期和版本提示。

## 实现范围

当前为明确标注的规则演示，未接入大模型、附件解析、公司内部系统或完整法律检索。输入只在当前页面内存中处理，没有后台案例存储、自动投诉或函件发送。刷新页面恢复虚构示例。服务器只提供静态资源，用户下载的文件由用户自行保存。

输入的名称、金额、日期和证据勾选均属于用户陈述，不代表已经核验。优先级阈值是演示中的内部跟进排序规则，不是法律标准或回款概率。设备故障责任、历史法律适用、利息、时效、管辖和程序条件须结合真实合同与材料另行审查。

## 文件结构

| 文件 | 用途 |
| --- | --- |
| `dist/index.html`、`dist/styles.css`、`dist/app.js` | 网页、样式与交互 |
| `dist/engine.js` | 可解释的回款分流与方案规则 |
| `dist/sources.js` | 固定官方来源目录，摘要不冒充法条原文 |
| `tests/engine.test.mjs` | 金额日期、场景分流及关键边界测试 |
| `server.mjs` | 仅供本机预览的静态服务 |
| [范围与验收](docs/DEMO_SCOPE.md) | 当前输入输出、业务分流及后续接入边界 |
| [法律与渠道核查说明](docs/LEGAL_SOURCES.md) | 官方来源、适用条件与更新说明 |


## 后续接入

优先用公司的匿名历史案例复核规则，再接入合同、验收单、维修工单与财务数据。接入大模型时保持现有结构化输入输出及来源目录，把模型建议与可核查事实、条文和渠道条件对应；完整法律版本检索与适用审查仍需单独实现。
