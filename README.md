# 企业回款方案生成演示

输入欠款金额、约定付款到期日和项目问题，生成维修整改、商务催收、法务路径与条件性投诉建议。业务优先级按用户确认的频率排列：设备销售、安装或维保，其次为一般企业应收账款，再次为工程结算。

当前已接入 DeepSeek 服务端调用。页面默认展示虚构示例的本机规则预览；只有点击“使用 AI 生成”，才会将本次填写的案情经同源服务端发送至 DeepSeek。AI 补充分析、分轨步骤、追问和沟通函，与固定规则及官方来源分别标注；失败时明确回退规则方案。

## 本地启动

需要 Node.js 20 或更新版本。在本目录执行：

```powershell
npm ci
npm run dev
```

打开终端打印的本机地址，默认是 `http://127.0.0.1:4173/`。默认端口被占用时会向后尝试端口。服务仅监听本机，关闭终端中的服务后即停止。

`npm ci` 安装构建用开发依赖 `esbuild@0.28.2`，模型请求使用原生 `fetch`，不依赖 DeepSeek 或 OpenAI SDK。未配置 AI 密钥时，可以使用规则预览，点击生成会明确提示规则回退。

## AI 配置与访问

部署环境将 `DEEPSEEK_API_KEY` 配置为 Sites runtime Secret；密钥只供服务端运行时使用，不进入浏览器、静态资源、源码包或文档。`DEEPSEEK_MODEL` 为可选服务端配置，默认 `deepseek-flash`。沿用现有站点的私有访问边界。

本机 Node 服务读取进程环境中的上述变量，**不会自动读取 `.env`**。`.env.example` 仅列出变量名并保留空密钥；复制为 `.env` 不会启用本机 AI。不要将真实密钥填入仓库文件或命令行参数。

浏览器只调用同源 `GET /api/health` 和 `POST /api/plan`。健康接口只报告服务是否配置及模型名，不测试上游生成，也不返回密钥。固定上游参数、输出 schema、回退和验证方法见 [DeepSeek 接入说明](docs/DEEPSEEK_INTEGRATION.md)。

## 演示功能

- 三类虚构示例，可直接修改金额、到期日、问题及补充条件；加载和切换示例不调用付费模型。
- 按维修、验收、资金、开票及争议情况组合行动步骤、负责人、材料和推进条件。
- 根据付款节点区分未到期、今日到期和逾期；金额及日期都有输入校验。
- 核查合同争议约定后分流诉讼或仲裁，不直接将“有欠款”认定为具备起诉条件。
- 中小企业款项投诉同时核查主体、事项及已有受理情况；纯企业经营货款不直接套用消费投诉。
- 展示证据清单、待补充问题、事实记录及规则沟通函；AI 成功后另增补充分析、分轨建议、追问及 AI 沟通函。
- 支持文本方案下载、草稿复制，以及通过浏览器打印或保存 PDF；导出保留生成方式和人工复核提示。
- 法律与渠道页提供固定官方全文或办事入口、条号定位、资料核查日期和版本提示。

## 实现范围

当前包含固定规则引擎与 DeepSeek 补充生成，尚未接入附件解析、公司内部系统或实时法律检索。AI 不能修改基础金额、日期、分流条件、既有动作和来源目录；不自动投诉、发函或提交法律程序。

本演示不保存历史案例，不记录案情或上游原始错误日志。输入和结果在当前页面使用，刷新后恢复虚构示例；用户下载的文件由用户自行保存。点击 AI 生成会把本次案情传给外部处理方 DeepSeek，本项目不承诺其数据保留政策。实际使用前应核对其适用条款和企业数据要求。

输入的名称、金额、日期和证据勾选均属于用户陈述，不代表已经核验。优先级阈值是演示中的内部跟进排序规则，不是法律标准或回款概率。设备故障责任、历史法律适用、利息、时效、管辖和程序条件须结合真实合同与材料另行审查。固定来源与 AI 建议均需复核，不代表已完成实时法律检索或法律适用审查。

## 文件结构

| 文件 | 用途 |
| --- | --- |
| `dist/index.html`、`dist/styles.css`、`dist/app.js` | 网页、样式与交互 |
| `dist/engine.js` | 可解释的回款分流与方案规则 |
| `dist/sources.js` | 固定官方来源目录，摘要不冒充法条原文 |
| `src/ai.js` | 固定上游调用、输出校验与规则回退 |
| `src/api.js` | 本机与 Worker 共用的同源 API |
| `server.mjs` | 本机静态资源与 API 服务 |
| `worker/index.js`、`scripts/build-worker.mjs` | Worker 入口与公开资源内嵌构建 |
| `dist/server/index.js` | 构建后的单文件 Worker，通过运行时绑定取得 Secret |
| `tests/*.test.mjs` | 规则、AI 边界、API 与 Worker 测试 |
| [DeepSeek 接入说明](docs/DEEPSEEK_INTEGRATION.md) | 配置、数据流、schema、回退与验证方法 |
| [范围与验收](docs/DEMO_SCOPE.md) | 原业务输入输出、场景分流及长期研发范围 |
| [法律与渠道核查说明](docs/LEGAL_SOURCES.md) | 官方来源、适用条件与更新说明 |

Worker 仅内嵌明确列出的公开资源，不向站点访问者提供 `src/`、服务端代码或 `.env` 文件；构建产物不内嵌真实密钥。业务及 AI 接入的当前状态以本 README 和接入说明为准。

## 验证

```powershell
npm test
npm run check
npm run build
```

`npm test` 先构建 Worker，再执行自动化测试；`npm run check` 检查 JavaScript 语法；`npm run build` 单独验证部署构建。测试数量以本次终端输出为准，模拟上游测试不等于真实模型生成验收。

启动本机服务后，可检查不产生模型调用的健康接口：

```powershell
Invoke-RestMethod 'http://127.0.0.1:4173/api/health'
```

截至 2026 年 11 月 10 日，`npm test` 的 94 项测试（含打包后的 Worker 测试）及 `npm run check` 已通过；另已完成真实 `GET /models` 鉴权检查及一次虚构设备案例的完整 AI 生成验证：HTTP 200、正常结束、4 轨建议通过 schema 与来源 ID 校验。该单例不代表所有场景质量均已验证。浏览器视觉排版、生成与回退提示、剪贴板、实际下载、打印及移动端交互仍待复核。完整检查步骤见 [DeepSeek 接入说明](docs/DEEPSEEK_INTEGRATION.md)。
