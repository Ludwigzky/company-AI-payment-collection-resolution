# 应收总览

应收总览集中展示当前账号已登记的付款节点、账龄与逾期，以及法律事项时间线。每个付款节点必须关联一个既有案件，同一案件可以登记多个节点。案件里的欠款估计值不会自动变成财务应收、开票金额或已到期款项。

## 三类记录分别登记

- 开票记录：发票编号、开票日期、分配至该节点的金额、有效／作废／红冲状态及备注。同张发票关联多个节点时应分别分配，避免重复汇总整张发票。空白表示未登记，不等于已开票金额为零。
- 财务确认应收：确认状态、确认日、账龄起算日、最新填报应收余额、余额截至日、财务凭证或确认依据。未确认的数额不纳入已确认应收汇总。
- 付款到期：确认状态、该节点未收金额及截至日、原约定到期日、当前确认到期日、付款条件和确认依据。已确认到期后再分别统计到期当日和逾期未收金额。到期日变更保留更改原因与旧版本；客户付款承诺作为独立事项登记，不直接覆盖合同日期。

财务余额与付款节点未收金额是独立填报口径；本期没有自动抵扣、回款分配、税务验票或ERP同步。金额均使用人民币，其他币种须在后续实现独立币种及折算规则后接入。

## 账龄与逾期分别统计

账龄依据明确登记的财务账龄起算日计算，不从发票日期、合同签订日或付款到期日推断。起算日未填或无效时显示待确认；即使余额已填，也保留未能进入账龄分组的金额及数量。

逾期天数依据已确认付款节点的当前到期日计算。未到期、到期当日、逾期、未收金额为零、条件待核查及日期未知分别展示。到期当日为0天，不算已逾期。条件尚未满足或到期依据未明确时不显示确定逾期天数。

汇总金额仅使用相应口径已登记且有效的数据，金额按分计算；不以缺失值代替零。统计日使用中国标准时间的当日；页面反映最新登记数据及各自余额截至日，不提供无法重建的历史财务报表。归档案件默认仍在总览范围内，归档不等于结清。

## 法律事项时间线

法律事项分别记录发生日期、送达状态与日期、证据材料、录入日期、核验状态及填报的复核人。业务提醒日期与人工核定法律期限分别登记。法律期限必须有核定依据、复核人和复核日期，页面仍明确为用户填报，不表示系统或律师已实际完成审查。

时间线保留合同、履约、催告、付款承诺、确认、程序申请及受理等事项。更正通过追加记录关联原事项完成，原记录保留并标明已被更正；旧提醒不再重复计入当前待办。案件表单已有的日期作为只读填报线索展示，不自动认定送达、中断、中止、期限起算或届满。

不会根据“欠款日期加三年”、催告记录的存在或单次材料识别，自动给出诉讼时效、受理期限或权利失效结论。完整法律判断继续进入案件工作台的法律依据核对流程。

## 保存与权限

付款节点及每次修改的历史快照保存在数据库；法律事项采用追加与更正链。读取、修改及附件关联始终检查当前用户、案件和节点，不将其他账号的数据纳入总览。关联案件已归档时保留查阅，恢复案件后再新增或修改。

本期为当前账号视角；企业多成员、部门权限、审批签名及外部财务系统连接尚未实现。

## 入口和验证

顶栏“应收总览”包含台账明细、账龄与逾期、法律时间线。点击“登记付款节点”关联既有案件后分别填写三个口径；没有登记的案件明确列出，不预填或推定财务余额。搜索匹配案件、客户或节点关键词，结果范围为匹配案件及其全部节点；打印使用与成功加载的数据相同的筛选快照。

数据表与触发器通过追加的 `0001_redundant_orphan` 迁移部署；旧迁移保持不变。单笔台账每次修改均保存完整版本，法律事项和历史表在数据库层禁止原位修改或删除。被更正的原事项仍可查看，当前提醒仅依据最新事项统计。
