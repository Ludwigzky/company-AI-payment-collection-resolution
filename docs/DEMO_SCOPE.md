# 企业回款演示范围与验收

本轮场景由用户于 2026 年 11 月 10 日确定：为一家公司建立回款解决方案生成演示，使用者输入欠款金额、欠款时间和项目问题，系统给出包含设备维修、法务诉讼、投诉渠道等路径的回款建议。

按业务发生频率，设备销售、安装或维保优先于一般企业应收账款，工程结算作为第三类示例。中国大陆商事场景是本轮实现假设，尚未绑定具体公司、地区或真实客户数据。

## 输入

| 信息 | 当前处理方式 |
| --- | --- |
| 欠款金额 | 必填，人民币元，必须大于零，最多两位小数 |
| 欠款时间 | 以“约定付款到期日”采集，用中国时区的分析日期计算相隔天数；付款条件仍待核实 |
| 项目问题 | 必填，自由文本；同时可勾选设备维修、验收、开票对账、资金、争议、失联等标签 |
| 补充条件 | 业务类型、双方企业类型、验收状态、争议解决条款、法院仲裁等受理状态和材料勾选 |
| 公司名称 | 选填，可用简称；缺失时沟通函保留待补充项 |

## 输出

输出包含整体推进策略、待核对金额、相对到期日、内部推进优先级、分工行动卡、建议顺序、证据缺口、事实记录、沟通函草稿和官方来源链接。每项行动写明原因、步骤、负责人、所需材料与适用条件。

| 分流条件 | 演示行为 |
| --- | --- |
| 设备或质量问题 | 核查故障和责任范围，形成维修、复验和付款沟通节点；不直接认定质量责任 |
| 验收或结算未完成 | 先核查合同条件、履行记录和具体异议，与无争议款项对账协同 |
| 尚未到期 | 输出到期前确认与履约核对，不标为逾期催收 |
| 一般货款且无设备问题 | 聚焦对账、书面付款安排和法务准备，不强制安排设备维修 |
| 选择仲裁约定 | 先核查条款有效性、范围与机构，再评估仲裁路径 |
| 争议约定未知 | 要求调取合同核查，不直接确定起诉或仲裁 |
| 中小企业债权人及特定债务人 | 核查采购合同、订约时划型、渠道受理及排除条件后评估款项投诉 |
| 已有法院仲裁等受理 | 提示核查投诉排除情形，不默认同一事项多渠道并行受理 |
| 主体资格未知或不匹配 | 输出待确认条件或合同争议路径，不将普通货款直接导向消费投诉 |
| 欠款时间较长 | 提醒核查完整时间线与时效因素，不仅凭天数认定时效届满 |

## 当前验收

规则测试覆盖输入错误、闰日与溢出日期、维修关键词及否定描述、三类业务、未到期款项、仲裁条款、材料不足、投诉主体与受理限制、长期欠款及恶意 HTML 文本输入。引擎返回纯文本，网页使用 `textContent` 展示案件描述和草稿。

已有验证为 16 项规则测试、脚本语法检查和本机静态资源 HTTP 检查。浏览器工具未完成视觉与交互检查；下载、复制、打印和响应式表现尚需实际浏览器复核。规则测试不等于法律适用评测或真实案件准确率。

## 与长期研发计划的关系

本演示确定了企业应收账款场景并跑通结构化输入到规则建议的代码路径。它不代表原项目的 LawQ 部署、向量检索、历史法律版本管理、证据附件解析、AI 文书生成或 Word 导出任务已经完成。

接入模型和真实材料前，需要补齐匿名案例评测、合同字段与维修工单解析、数据存储与访问控制、法律数据及版本检索、适用性审查和成本预算。已有规则可以作为模型输出的检查条件与回退路径。
