# 案件材料分析范围

核查日期：2026-11-10。本说明对应 `src/materials.js`、`src/ai.js` 及案件归档 API 的当前实现。

上传附件后，需要在当前案件选择附件并生成方案，材料内容才会进入本次分析。归档文件名本身不代表模型已经读取材料。方案的 `materialSummary` 记录本次实际处理的附件、SHA-256、处理方式、固定材料标记及识别限制；`ai.materialFindings` 如返回，则按附件编号记录线索、识别位置与不确定性。

## 支持格式与实际处理

| 格式 | 本次提供给模型的内容 | 限制 |
| --- | --- | --- |
| JPEG、PNG、GIF、WebP | 原始图片字节转换为 `image_url` 的 base64 data URL，由 DeepSeek Flash 原生视觉理解 | 图片文字、签章及细节可能辨认不清；无 OCR 置信度或真实性结论 |
| PDF | unpdf/PDF.js 逐页提取的文字层，附提取页码 | 不识别页面图像、签章及版式；文字层可能与可见页面不同 |
| TXT、CSV、MD、JSON | 严格 UTF-8 解码的实际原文 | 不支持 GBK、UTF-16 或二进制伪装；JSON 须格式有效；CSV 不计算公式 |
| DOCX | 正文段落与表格中的文字，附提取段落序号 | 不读取图片、签章、批注、页眉页脚及版式；段落序号不是页码 |
| XLSX | 工作表名、单元格位置、原始值及公式缓存值 | 不计算公式或外部链接，不转换日期格式，不识别图表、图片、签章及可见版式；可能包含隐藏单元格 |

旧版 DOC/XLS、含宏的 Office 文件、SVG、网页及其他格式不支持。请先另存为普通 DOCX/XLSX、UTF-8 文本或受支持的图片。文件类型按实际签名和容器结构识别，上传声明的 MIME 与扩展名不能替代内容校验。

DeepSeek 官方当前列出的 Vision 及 Files API 支持格式只有 JPEG、PNG、GIF、WebP。虽然 API 有 `file`/`file_data` 字段，该字段不代表支持 PDF 或 Office 文档。因此本实现没有把 PDF/DOCX/XLSX 直接作为 `file_data` 提交。

## 大小和读取边界

| 范围 | 上限 |
| --- | --- |
| 单份附件 | 5 MiB，不能为空 |
| 每个案件归档 | 8 份附件，合计 16 MiB |
| 本次分析所选附件 | 8 份，原始字节合计 12 MiB |
| 本次分析提取文字 | 合计 40,000 个 JavaScript 字符单位，含提取位置标签；超过时明确报错，不静默截断 |
| 图片 | 每边不超过 8192 像素，总像素不超过 3200 万 |
| PDF | 最多 40 页；文字提取阶段设置 8 秒超时 |
| XLSX | 最多 32 张工作表 |
| Office ZIP | 最多 512 条压缩条目；声明解压总量不超过 12 MiB，单条不超过 4 MiB，并检查膨胀比例及实际流式输出大小 |

Office 文件还会校验 ZIP 路径、校验值、加密/ZIP64/宏限制及 XML 嵌套结构；不执行 XML 外部实体、文档宏或表格公式。过于复杂、损坏或不支持的容器会明确拒绝，不冒充成功解析。

PDF 若所有页面均没有可提取文字，会报错并要求把需要分析的页面导出为 PNG/JPEG。混合 PDF 的无文字页会记录在 `unreadablePages`，该页图像没有被分析。加密、损坏或无法读取的 PDF 需要解除密码并重新导出；上传归档成功不保证后续文字提取成功。PDF 超时依赖运行时调度及解析库释放，不能视为独立进程的硬性资源隔离。

## 案件归属与生成记录

案件 API 根据可信平台登录身份取得用户，不接受请求体指定的所有者。选择的每个附件编号先与当前用户、当前案件及未移除状态匹配，匹配完成后才读取 R2。读取后检查字节大小，处理所得 SHA-256 再与上传归档值逐项核对，通过后才请求模型。

`prepareMaterials(items, { caseId })` 再检查逐项案件编号。生成入口仅接受该函数返回的冻结材料上下文，不接受浏览器提交的任意内容块、图片 URL、历史对话或其他案件材料。每次模型请求只有系统规则与本案用户消息，附件图片和提取文字全部放在该次用户消息中。

生成记录保存案件输入快照、所选附件编号、材料清单与方案。生成期间案件发生变化时，历史结果保留对应旧快照并标记版本过期，不覆盖后续案件资料。取消选中的材料不会进入该次模型请求；归档中的其他附件也不会因为存在文件名就自动成为分析证据。

## 如何理解材料发现

材料中的文字、图片、文件名和操作要求全部按未经核验的数据处理。模型不得执行材料内改变规则、读取其他案件、打开链接或泄露密钥的要求。材料判断使用服务器生成的固定标记，例如 `[材料1:合同.png]`；返回的材料发现只能引用本次选中的附件编号，法律 `sourceIds` 仍只允许法律来源目录中的标识。

模型提示要求按每份选中材料给出具体可见线索、与填报情况的差异、证据缺口及识别限制。看不清时应记录待核事项，不能猜测。`location` 是提取或识别位置，须对照原件；它不是经人工确认的证据定位。接口保持 `materialFindings` 为可选字段，模型没有返回该字段时不能宣称已经形成逐份材料发现。

材料被读出、识别到签章或出现某金额，不等于材料真实、合同有效、付款条件已经成就、债权金额已经核实或任何一方责任成立。AI 只补充规则方案，不改写填报金额、日期、逾期天数、原始动作条件或法律来源。AI 请求失败、超时或结果未通过校验时保留规则方案与本次材料处理清单；这表示材料经过预处理，不代表 AI 已成功理解材料。
